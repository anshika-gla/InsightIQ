# InsightIQ

### Intelligent Analytics Query Engine

> Ask business questions in natural language. Get analytical results with transparent logic, confidence, and explanations.

InsightIQ is a GenAI-powered analytics query engine that converts natural-language business questions into structured analytical plans and executes them against business datasets using a deterministic Pandas-based engine.

## Overview

InsightIQ provides a natural-language interface for business analytics. A user can ask questions without writing SQL, and the system:

1. Understands the query using GenAI.
2. Generates a structured query plan.
3. Validates the plan.
4. Executes the plan using deterministic Pandas operations.
5. Returns the result, logic, confidence score, and explanation.

### Core Pipeline

```text
User Query
    ↓
Natural Language Understanding
    ↓
GenAI Query Planner
    ↓
Structured Query Plan
    ↓
Plan Validation
    ↓
Deterministic Pandas Execution
    ↓
Result + Logic + Confidence + Explanation
```

## Problem Statement

The objective of InsightIQ is to build a system that:

- Understands natural-language business queries.
- Maps business terminology to dataset fields.
- Converts queries into executable analytical logic.
- Executes the logic against the provided datasets.
- Supports simple and complex analytical queries.
- Returns correct and explainable results.
- Provides a confidence score for every query.
- Handles unsupported or insufficient-data queries gracefully.

## Key Features

### Natural Language Analytics

Example queries:

```text
What are the total sales?
```

```text
What are the top 2 cities by profit?
```

```text
What is the average order value by region?
```

```text
Which region missed its target in February 2024?
```

```text
What are the top 3 customers in each region by revenue?
```

### GenAI Query Planning

GenAI converts the user's question into a structured query plan.

Example:

```json
{
  "operation": "top_n",
  "metric": "revenue",
  "group_by": ["region", "customer_id"],
  "limit": 3,
  "order": "desc",
  "nested": true
}
```

The generated plan is validated before execution.

### Deterministic Execution

Numerical calculations are performed by Python and Pandas rather than being generated by the LLM.

This provides:

- Reproducible calculations
- Better numerical reliability
- Easier debugging
- Controlled execution
- Separation between AI planning and data processing

## Supported Analytics

| Operation | Description |
|---|---|
| Aggregation | Sum, average and count |
| Grouping | Analyze metrics by business dimensions |
| Filtering | Filter records using query conditions |
| Ranking | Rank groups by a selected metric |
| Top-N | Return highest or lowest N results |
| Nested Top-N | Top-N items within each group |
| Percentages | Calculate contribution percentages |
| Target Comparison | Compare actual performance against targets |
| Time Analysis | Analyze metrics across time |
| YoY Analysis | Calculate year-over-year growth when data is sufficient |
| AOV | Calculate average order value |
| Derived Metrics | Calculate revenue from raw fields |

## Safe AI Design

InsightIQ separates AI-based planning from actual data execution.

### GenAI is responsible for:

- Understanding the user's question.
- Identifying the metric.
- Identifying grouping fields.
- Identifying ranking or comparison requirements.
- Generating the structured query plan.

### The deterministic engine is responsible for:

- Loading the dataset.
- Applying filters.
- Calculating metrics.
- Performing aggregations.
- Ranking results.
- Performing comparisons.
- Returning the final result.

```text
GenAI
  ↓
Structured Plan
  ↓
Validation
  ↓
Deterministic Execution
```

The LLM does not directly execute arbitrary Python code.

## Query Execution Flow

For:

```text
What are the top 3 customers in each region by revenue?
```

The system:

1. Receives the natural-language query.
2. Generates a structured query plan.
3. Validates the plan and referenced fields.
4. Calculates revenue.
5. Groups records by region and customer.
6. Ranks customers within each region.
7. Selects the top 3.
8. Returns the result with logic, confidence, and explanation.

## Example Queries

### 1. Total Sales

```text
What are the total sales?
```

Result:

```text
6134.4
```

### 2. Top 2 Cities by Profit

```text
What are the top 2 cities by profit?
```

Result:

```text
New York        200
San Francisco   180
```

### 3. Average Order Value

```text
What is the average order value by region?
```

Formula:

```text
Average Order Value = Total Revenue / Unique Orders
```

### 4. Target Comparison

```text
Which region missed its target in February 2024?
```

The result includes:

- Region
- Actual revenue
- Target revenue
- Difference
- Achievement percentage
- Target status

### 5. Contribution Percentage

```text
What is the sales contribution percentage by category?
```

Formula:

```text
Contribution % = Group Revenue / Total Revenue × 100
```

### 6. Nested Top-N

```text
What are the top 3 customers in each region by revenue?
```

The system ranks customers independently within every region.

### 7. Year-over-Year Analysis

```text
What is the year-over-year growth?
```

If sufficient historical data is unavailable, the system returns:

```text
status: insufficient_data
```

instead of fabricating a value.

## Error Handling

The system avoids fabricating answers for unsupported queries.

For example:

```text
What is the weather in Delhi?
```

is outside the scope of the provided business datasets.

The system reports that the requested analysis is not supported.

Other handled cases include:

- Unknown columns
- Unsupported operations
- Invalid query plans
- Invalid grouping fields
- Insufficient historical data
- Unsupported analytical requests

## Design Trade-offs

### GenAI vs Deterministic Execution

**Decision:** Use GenAI for query interpretation and planning while keeping calculations deterministic.

**Benefits:**

- Reliable numerical results
- Reproducibility
- Easier debugging
- Safer execution

**Trade-off:**

The execution engine needs explicit support for each analytical operation.

### Pandas vs Database

**Decision:** Use Pandas because the supplied dataset is CSV-based and relatively small.

**Benefits:**

- Simple implementation
- Fast development
- Strong analytical functionality
- Easy data transformation

**Trade-off:**

Very large datasets would be better handled by a database or distributed processing system.

### Local Fallback Planner

A local fallback planner is available for supported common analytical queries when the external GenAI service is temporarily unavailable.

**Trade-off:**

The fallback planner supports fewer natural-language patterns than the GenAI planner.

---

## Limitations

- The system is optimized for the provided dataset structure.
- The deterministic engine supports a defined set of analytical operations.
- Very large datasets may require database-backed processing.
- Complex unseen queries may require additional planner and executor capabilities.
- The fallback planner has narrower language coverage than the GenAI planner.
